# Employee Flight Risk Classification Model

## Overview
This project predicts whether an employee may voluntarily resign within the next **3 months** using the binary target `resign_3m`.

The repository is organized around a clear machine-learning lifecycle:
1. **Environment & Configuration**
2. **Data Ingestion & Validation**
3. **Exploratory Data Analysis**
4. **Feature & Target Preparation**
5. **Baseline Modeling**
6. **Class-Imbalance Strategy**
7. **Model Tuning & Cross-Validation**
8. **Threshold Optimization**
9. **Final Evaluation**
10. **Explainability with SHAP**
11. **Artifact Persistence & Governance**
12. **FastAPI Serving**
13. **Retention Agent / LLM Layer**
14. **Notebook & Streamlit Demonstration**

The canonical production path is:

```text
Employee Data
    ↓
Preprocessing
    ↓
SMOTE applied only during training
    ↓
LightGBM classifier
    ↓
Cross-validation and hyperparameter tuning
    ↓
Out-of-fold threshold optimization
    ↓
Untouched test-set evaluation
    ↓
Saved full pipeline + metadata
    ↓
SHAP explanations on fitted LightGBM model
    ↓
FastAPI endpoint
    ↓
Retention Agent
    ↓
Streamlit / notebook demo
```
This GitHub-ready version makes the workflow internally consistent:

- One consolidated import/configuration cell.
- One untouched stratified test set.
- Four baseline strategies for comparison.
- A single canonical SMOTE + LightGBM tuning path.
- PR AUC as the primary tuning metric because resignation is the minority class.
- Threshold tuning using **out-of-fold training predictions**, not the test set.
- One final evaluation on the untouched test set.
- One saved production artifact: the **complete fitted pipeline**.
- One shared utility module used by the notebook, FastAPI, the agent, and Streamlit.
- SHAP is calculated on the fitted LightGBM classifier after applying the fitted preprocessing steps.
- SMOTE is never applied during inference.
- Databricks credentials and endpoint URLs are read from environment variables rather than committed to GitHub.

## Dataset

The notebook looks for the encoded employee dataset in the following order:

1. `/mnt/data/employeeEncoded_data.csv`
2. `data/employeeEncoded_data.csv`
3. `employeeEncoded_data.csv`

The target variable is:

```text
resign_3m
0 = employee stays
1 = employee voluntarily resigns within 3 months
```

The legacy `leave` column is excluded from the feature set to reduce target leakage risk.

## Model Strategy

The notebook compares four baseline approaches:

| Model | Imbalance Strategy |
|---|---|
| Logistic Regression | `class_weight="balanced"` |
| Logistic Regression | SMOTE |
| LightGBM | `scale_pos_weight` |
| LightGBM | SMOTE |

The final tuning workflow focuses on **SMOTE + LightGBM**. SMOTE is placed inside an `imblearn` pipeline so synthetic observations are created only inside each training fold.

## Evaluation Metrics

Because voluntary resignations are the minority class, overall accuracy is not sufficient.

The notebook reports:

- ROC AUC
- PR AUC / Average Precision
- Accuracy
- Balanced Accuracy
- Recall for leavers
- Precision for leavers
- F1 for leavers
- Brier Score
- Employees flagged
- False positives
- Missed leavers
- Correctly identified leavers

PR AUC is used as the primary model-selection metric during cross-validation.

## Threshold Optimization

The classification threshold is tuned using out-of-fold probabilities generated only from the training population.

This prevents test-set leakage.

The notebook evaluates thresholds from `0.10` through `0.90` and selects the threshold that maximizes the F1 score for the minority `Leave` class.

The final threshold is stored in `model_metadata.json` and reused by downstream applications.

## SHAP Explainability

The production object is a pipeline:

```text
Median Imputation → Standard Scaling → SMOTE → LightGBM
```

For prediction, the complete pipeline is used.

For SHAP:

1. The employee row is passed through the fitted imputer.
2. The fitted scaler transforms the row.
3. SMOTE is skipped because SMOTE is training-only.
4. `TreeExplainer` explains the fitted LightGBM classifier.

This preserves the production scoring logic while keeping SHAP technically aligned with the model input space.

## Optional Databricks LLM Recommendation Layer

The retention agent can send the prediction and top SHAP drivers to a Databricks serving endpoint.

Set credentials locally:

```bash
export DATABRICKS_LLM_ENDPOINT="https://<workspace-host>/serving-endpoints/<endpoint-name>/invocations"
export DATABRICKS_TOKEN="<token>"
```

Do not commit tokens or production endpoint credentials to GitHub.

If the endpoint or token is unavailable, the agent returns a deterministic fallback HRBP recommendation structure.

## Responsible Use

This model should be treated as a **decision-support tool**, not as an automated employment decision system.

Recommended controls include:

- Never present a risk score as certainty that an employee will resign.
- Do not use protected-class attributes or sensitive personal inferences.
- Require human review before retention action.
- Validate data quality, recency, and business context.
- Monitor calibration and performance over time.
- Monitor subgroup performance and potential disparate impact.
- Version the model, feature list, threshold, and metadata together.
- Maintain an audit trail of model changes and downstream use.
- Use supportive retention actions rather than punitive actions.
